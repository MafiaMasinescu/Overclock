# Task 11.5: Pure Research lifecycle and final Museum result

## Boundary

Implement only the pure Research lifecycle calculation. Do not register a tick system, modify
`SimCore`, add commands, or apply the result to authoritative state.

## Contract

- Reconcile locked nodes to `available` in deterministic `sortOrder`, then lexical-ID order.
- Eligibility uses completed prerequisites, present Evidence Tags, and unique matching passed best
  benchmark runs. Cash and Research Data are not eligibility requirements.
- Completed, active, cancelled, and valid available statuses are monotonic. Contradictory supplied
  states fail validation.
- Active Research consumes the current Compute-owned Research result and advances by
  `deliveredUsefulComputeFlops * 0.1`, without rounding or surplus carry.
- Completion clears the active record and reconciles newly available nodes in the same calculation.
- Completing the unique final node sets the approved campaign flags and creates exactly one
  `museum-vacuum-tube-final` snapshot from the current Compute, benchmark, facility, module, and
  thermal inputs.
- Module and feature unlocks remain derived from completed Research; no authoritative unlock maps
  are added.
- The result is detached and deeply immutable. The private witness covers every authoritative input
  used by the calculation and is not part of the result state.

## Implementation and verification

1. Add `src/sim/research/researchDomain.ts` with the pure calculation, derived unlock helpers, and
   same-calculation witness validation.
2. Align the fixed Museum snapshot ID in the Research state validator with the approved contract.
3. Add focused lifecycle, eligibility, progress, final Museum, ownership, determinism, serialization,
   and RNG tests in `tests/unit/researchDomain.test.ts`.
4. Run focused tests, formatting, lint, strict TypeScript, content validation, build, diff check,
   and forbidden API/import scans. Leave all changes uncommitted.
