# Task 11.4 Atomic Research Commands Implementation Plan

> Execute inline in the existing workspace. Do not commit or push; preserve Tasks 11.1 through
> 11.3 and stop before Research progress or tick behavior.

**Goal:** Add atomic `START_RESEARCH` and `CANCEL_RESEARCH` handlers through the existing command
processor, with deterministic validation precedence, exact microdollar accounting, rollback, and
no immediate Compute recalculation.

**Architecture:** Create a content-injected `createResearchCommandHandlers` factory returning only
the two Research handlers. The handlers mutate only the command candidate supplied by the existing
`CommandProcessor`; no Research execution path, event system, tick stage, or Compute projection is
added.

**Rules:**

- `START_RESEARCH` checks active state first, then startability, prerequisites/evidence/benchmarks,
  reservation share, cash credit boundary, and Research Data in the approved order.
- Benchmark satisfaction requires an exact unique history mapping whose benchmark ID matches and
  whose run passed.
- Accepted starts charge cash with integer microdollar helpers, charge Research Data, preserve
  tick/RNG/last-tick expense, and create active progress at positive zero.
- `CANCEL_RESEARCH` requires an exact active-node/status match, changes only Research status/active,
  refunds nothing, and discards progress.
- Rejections and authoritative numeric contradictions remain atomic through the existing command
  transaction and validation path.
- No current Compute capacity is read and no Compute state is recalculated during command-only
  processing.

**Verification:** Focused Research command/state tests, command pipeline regressions, Task 4 money
and credit tests, Task 9 cache tests, Task 10 command tests, Prettier, ESLint, strict TypeScript,
content validation, production build, diff check, and forbidden API/import scan.
