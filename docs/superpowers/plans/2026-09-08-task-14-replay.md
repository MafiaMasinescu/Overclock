## Objective

Add a headless, deterministic replay layer around the real production `SimCore` entry points. The layer must record the exact ordered operations that affect simulation execution, replay them against a detached initial state and immutable content fingerprint, compare command/tick/fatal outcomes, produce first-difference diagnostics, and create verified nonfatal resume artifacts. Replay metadata remains outside authoritative `GameState`, uses canonical JSON, and cannot introduce browser, filesystem, wall-clock, or random dependencies into `src/sim`.

## Design constraints

1. Preserve the current `CommandReceipt`, `CommandResult`, `SimCore`, queue, tick-system, RNG, and canonical-hash contracts unless the Task 14 contract explicitly requires a new additive API.
2. Keep the existing direct `new SimCore({ initialState, commandHandlers, tickSystems })` path unchanged for compatibility tests.
3. Add one production factory that registers every existing command handler and every existing tick-system factory exactly once, including the combined Task/Benchmark stage.
4. Journal operations in exact caller order: `enqueue`, clock application, `processPendingCommands`, and `step(n)`. Do not infer or collapse operations.
5. Use client-supplied command IDs and preserve parsed command payloads, including duplicate IDs.
6. Validate raw replay data for canonical serializability, strict shapes, exact keys, standard prototypes, dense arrays, and detached ownership before schema validation.
7. Treat unexpected simulator invariant errors as fatal terminal outcomes with normalized diagnostics and no stack/cause leakage in the serializable log.
8. Checkpoint only at sequence zero and explicit operation boundaries; do not add per-operation state hashes to the log.
9. Keep content fingerprinting deterministic and locale-independent using the approved content projection.
10. Use TDD: every new production behavior gets a failing focused test before implementation, then green tests and a refactor pass.

## Implementation steps

### 14.1 — Contracts, parser, state-independent fingerprint, and validators

- Add replay version/protocol constants and exact operation, outcome, checkpoint, terminal, replay-log, divergence, runner-result, and resume-artifact types.
- Add strict runtime parsing for replay operations, logs, checkpoints, terminal records, and resume artifacts.
- Add canonical simulation-content projection and hash using `contentVersion`, modules, tasks, research, era, and balancing while excluding locales.
- Add structural validation for contiguous operation sequence, exact operation/outcome pairing, terminal rules, checkpoint rules, queue sequence bounds, and immutable detached data.
- Add unit tests for strict parsing, extra keys, sparse arrays, custom prototypes, non-finite values, duplicate command IDs, malformed terminal entries, content hash locale exclusion, and compatibility.
- Add ADR-0020 and working status documentation with the exact next subtask.

### 14.2 — Production composition and operation journal

- Inspect all current command and tick factories and create a single production composition factory with duplicate-key assertions.
- Add an isolated initial queue sequence option without changing the default direct `SimCore` constructor behavior.
- Add a journal/recording wrapper around real `enqueue`, `applyClockCommand`, `processPendingCommands`, and `step` entry points.
- Preserve exact operation order, queue sequence, command outcomes, step results, and partial command commits.
- Add queue cursor/read-only boundary support required by replay and resume without exposing mutable queue internals.
- Add tests for factory completeness, isolated runtimes, exact operation sequencing, same-tick operation distinctions, queue exhaustion, and no implicit flush.

### 14.3 — Recorder, checkpoints, fatal boundaries, and ownership

- Build a recorder that starts from a detached new-game or explicit initial snapshot and stores seed, content version/hash, initial state hash, tick, queue sequence, and immutable journal entries.
- Add initial checkpoint at `afterSeq: 0`, explicit checkpoint creation only at empty-queue boundaries, deduplication, and final terminal checkpoint.
- Normalize fatal `SimulatorInvariantError` data with command ID and tick/origin while excluding stack, cause, and environment paths; freeze the session after fatal termination.
- Reject recorder state replacement or external mutation and prove all log artifacts are detached and deeply immutable.
- Add tests for fatal commands with pending queue entries, partial commits, checkpoint deduplication, state hash coverage, and no per-operation checkpoint hashes.

### 14.4 — Replay runner and divergence diagnostics

- Build a runner that validates protocol/content/initial-state compatibility and replays through the production factory and real entry points.
- Compare enqueue receipts, command results, clock outcomes, step results, state hashes, queue sequences, checkpoints, and terminal outcomes exactly.
- Return the prescribed matched, matched-fatal, invalid-log, incompatible, invalid-initial-state, limit-exceeded, diverged, and internal-error statuses.
- Produce the first divergence path with operation sequence, expected/actual values, and safe diagnostic context.
- Enforce default maximum operation and tick budgets without silently truncating a valid log.
- Add tests for all statuses, first-difference selection, incompatible content, malformed logs, exact fatal matching, and replay determinism.

### 14.5 — Verified resume and cross-domain determinism

- Add resume artifacts only at verified nonfatal empty-queue boundaries, bound to replay hash, full state hash, tick, and next queue sequence.
- Resume on a cold production runtime from the detached state and remaining operations; reject tampered or stale artifacts.
- Prove exact remaining outcomes and final state/hash equivalence with uninterrupted replay across command, tick, RNG, Task, Research, Benchmark, Blueprint, Thermal, Power, Overclock, and Compute domains.
- Add exact-100 deterministic record/replay and resume tests with unchanged RNG where the contract requires it.
- Verify private recorder/replay state is isolated per runtime and never enters authoritative state, snapshots, hashes, saves, receipts, or public command contracts.

### 14.6 — Performance, diagnostics, and permanent documentation

- Add a realistic audited replay fixture using existing production content and mixed command/tick operations.
- Measure direct production tick, recording wrapper, playback, checkpoint creation, fatal terminal handling, and cold construction separately with documented warm-up and samples.
- Preserve the `<4 ms` production tick gate and apply the approved replay wrapper/playback targets without hiding setup or reducing fixture complexity.
- Add a permanent replay diagnostic and finalize ADR-0020, TDD, Phase 1 plan, README, and PROJECT_STATUS; remove temporary Task 14 working status.
- Run all focused, unit, determinism, validation, build, drift, forbidden-domain, and performance checks.
- Perform final scope audit and leave the Task 14 diff uncommitted for the separate checkpoint prompt.
